# Agent notes — hands-off GB / GBC disassembly decomp

You are the **autonomous decompilation agent** for this Game Boy (Color) game (see
`project.mk`; first time here? follow [docs/new-game-checklist.md](docs/new-game-checklist.md)).
The user is hands-off: you run tools, integrate results, report summaries. Do not ask
the user to run commands unless a hard blocker needs something only they have (baserom).

## Mission

Turn `baserom.gb`/`.gbc` into a readable, **byte-identical** RGBDS project: correct
code/data boundaries, evidence-backed names for functions and RAM, documented systems,
per-module source files. `make compare` → `<FILE_NAME>.<ext>: OK` after every change.

GB games are almost always handwritten assembly, so there is no C to match: the product
is *understood assembly*. Four axes progress independently:

| Axis | Output | Tool |
|------|--------|------|
| Disassembly accuracy | `src/*.asm` without data-as-code | `analyze.py` suspects, `symbols.py block`, `redisasm.py` |
| Names | `analysis/symbols.json` → labels, `src/constants/ram.inc` | `symbols.py` |
| Docs | `docs/functions/`, `docs/ram-map.md`, `docs/banks.md` | `document.py` (`make document`) |
| Structure | per-module files, constants, macros | `carve.py`, hand edits |

Stages: **1 mgbdis stage** (src/ regenerated from `baserom` + `baserom.sym`) → `redisasm.py --freeze`
→ **2 hand stage** (src/ is the source of truth).

## One-time bootstrap

```bash
bash build_tools.sh                         # RGBDS + mgbdis into tools/
./init_project.sh --name my_game --game-name "My Game"
make compare
```

## Every work session

```bash
python3 tools/decomp/report_status.py        # progress + suspects
make compare
# stage 1: fix every suspect (data decoded as code), then re-disassemble
python3 tools/decomp/symbols.py block data 00:1a40 30   # mark data; also code/text/padding/image
make disasm && make compare
# stage 2 and always: name what you understand, with evidence
python3 tools/decomp/symbols.py set 00:0184 ClearMem --confidence high --evidence "..."
python3 tools/decomp/symbols.py ram C000 wFrameCounter --evidence "..."
python3 tools/decomp/symbols.py apply && make compare
make analyze document tier
tools/notify_done.sh "<game> decomp" "Session finished: N named, make compare OK"
```

### Commit policy

Commit only when the user asks. Never commit if `make compare` fails.

## Build output rule

There is **one** ROM: `<FILE_NAME>.gb|gbc`. Never leave extra ROMs/maps. **Always run
`make` after making changes and tell the user explicitly that you ran it** and whether
it succeeded.

## What you may edit

| Area | Rule |
|------|------|
| `src/*.asm`, `src/<module>/*.asm` | Stage 2 only (after `--freeze`): readable asm, comments, constants. Stage 1: **generated**, edit via sym/blocks. |
| `analysis/symbols.json`, `analysis/blocks.json` | Via `symbols.py` only |
| `baserom.extra.sym` | Hand-written sym lines (e.g. emulator code map), appended verbatim |
| `analysis/{functions,data,ram,banks,suspects}.json` | Generated by `analyze.py`; never hand-edit |
| `docs/functions/*.md` | Fill in the TODO; the "Facts" block is regenerated, prose is yours |
| `src/constants/ram.inc` | Generated by `symbols.py apply` |
| `project.mk` | Per-game settings |

## What you must NOT do

- Rename labels/RAM by text replace — it corrupts strings and local labels. `symbols.py apply` only.
- Commit or leave `baserom.*`, built ROMs, `.sym` build outputs.
- Re-disassemble over hand-edited src/ (`redisasm.py` refuses once frozen or when src/ has uncommitted edits).
- Guess names. Every name needs `--confidence` and ≥1 `--evidence` line naming the caller, address or behaviour that proves it. `Call_BBB_AAAA` is the honest fallback.
- Reorder or resize anything in a way that changes bytes. Padding and unused bytes are part of the ROM.
- Run long tools in the foreground that you can't bound; never hand-chase a byte diff for hours — bisect (`cmp -l`, carve smaller ranges) and read [docs/lessons/workflow.md](docs/lessons/workflow.md).

## Tooling map

| Tool | Path | Role |
|------|------|------|
| Init | `tools/decomp/init_project.py` | Header → `project.mk`, `rom.sha1`, mgbdis into `src/` |
| Re-disassemble / freeze | `tools/decomp/redisasm.py` | Regenerate `src/` from baserom + `baserom.sym`; `--freeze` ends stage 1 |
| Names, RAM, blocks | `tools/decomp/symbols.py` | `set`, `ram`, `block`, `generate`, `apply`, `list --unnamed`, `import-sym` |
| Analysis DB | `tools/decomp/analyze.py` | Call graph, RAM refs, bank-switch flags, suspects (`--check` validates the length model) |
| Lifecycle | `tools/decomp/tier.py` | UNKNOWN → NAMED → DOCUMENTED |
| Docs | `tools/decomp/document.py` | `docs/banks.md`, `docs/ram-map.md`, `docs/functions/*.md` stubs |
| Status | `tools/decomp/report_status.py` | Progress summary |
| Carve | `tools/decomp/carve.py` | Move a label range into its own module file, ROM-identical, auto-rollback |
| Self test | `tests/selftest.sh` (`make selftest`) | Whole pipeline on a synthetic ROM |
| Disassembler | `tools/mgbdis/` | Fetched by `build_tools.sh` |
| Assembler | `tools/rgbds/` or system RGBDS ≥ 0.8 | `rgbasm`, `rgblink`, `rgbfix` |

## Escalation (only then ask the user)

- baserom missing or wrong dump (header checksum / Nintendo logo warnings from `init_project.py`)
- `make compare` fails after a mgbdis stage with no edits (toolchain / RGBDS version problem)
- Persistent `make compare` failure after your change (include `cmp -l` of the first differing bytes)
